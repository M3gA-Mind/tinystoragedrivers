# Uniform schema (v2): implementation

Implements [`../specs/schema-v2.md`](../specs/schema-v2.md). Each task starts with a failing test, lands as its own commit, and keeps `cargo fmt --check`, `clippy -D warnings`, `build` and `test --all-features` green. The first published release containing all tasks is tagged **v1.0.0**: the physical layout change is not backwards compatible.

## Assumptions

- Owners migrate in their own repositories after v1.0.0 is tagged. Their steps are written against the v1 shapes listed in the spec's catalogue.
- v1 strings remain valid `Scope` values throughout. Only new writes use the grammar.
- OpenHuman patches every module's git-tag dependency onto one vendored checkout, so all owners resolve the same tsd during the transition.

## This repository

1. **Scope grammar** (`crates/tinystoragedrivers-core/src/scope/`)
   - `Scope::tenant`, `cluster`, `agent`, `module`, `tenant_scope` and `parse`, plus the segment hash (base32 SHA-256, 26 characters).
   - Tests:
     - round-trips
     - the hash boundary at 96 bytes
     - `u:a` versus `u:ab` tenant separation
     - v1 strings still accepted by `Scope::new`
2. **`Key`** (`core/src/key/`, new)
   - `Key::of`, `Key::split` and `Key::ulid`.
   - Escaping and hashed-fallback tests at 512 bytes.
   - Add the `ulid` workspace dependency.
3. **Record metadata** (`core/src/document/`)
   - `Meta` on `Document`.
   - Reserved paths `_schema`, `_created_ms`, `_updated_ms`, `_expires_ms` in `filter/`.
   - `expires_ms` written through `Put`.
   - The memory driver implements it.
   - New conformance module `conformance/schema.rs`, enabled for every driver.
4. **Registry** (`core/src/schema/`, new)
   - `Schema`, `Item`, `ScopeClass`, `Step`, `Registry::compose`, and the runner over `tsd.migrations`.
   - Tests:
     - each composition refusal
     - step resume after an injected failure at batch *n*
     - deterministic re-run
     - `Unavailable` on writes during migration
5. **Primitives** (`core/src/primitives/`, new)
   - `Leases`, `Kv`, `Counters`, `Repo<T>`.
   - Contention tests in conformance: two tasks racing for `acquire`, `next` and `update`.
6. **Stream sealing** (`core/src/stream/`)
   - `seal`, `SealPolicy`, read equality.
   - `Conflict` on appending to a sealed stream.
   - Crash points: after the blob, after the head.
7. **Maintenance** (`core/src/capabilities/`)
   - Add `Maintenance` and `ScopeEnumeration` capabilities, `Maintenance::run`, `checkpoint(Truncate)`, and `StorageBackend::scopes(prefix)`.
8. **SQLite v2 layout** (`crates/tinystoragedrivers-sqlite/src/sql/`)
   - Physical tables per spec §7, with zstd bodies over 4 KiB and generated index columns.
   - The in-place v0→v2 upgrade, tested against a fixture produced by v0.11.0 (`tests/fixtures/v0_11.db`, generated by a script checked in beside it).
   - `auto_vacuum=INCREMENTAL`.
   - Remove `database(name)` and directory mode.
9. **MongoDB, File, S3**
   - Metadata fields `_schema`, `_c`, `_u`, `_x`, with the TTL index on `_x`.
   - Sealing.
   - `Unsupported` maintenance on drivers that have none.
   - The full conformance suite on every driver.
10. **Bus contract** (`tinystoragedrivers-bus`): carry `Meta` and the seal and registry calls over the module wire. Bump the contract version.
11. **Docs**
    - README and `storage-ports.md` cross-links.
    - Mark the spec Implemented.
    - Release **v1.0.0** through `release.yml` (bump=major).

## Downstream (other repositories, after v1.0.0)

These run in order. Each item is one PR in its owner's repository.

1. **tinyagents**
   - `storage_schema()` for harness, session, ledger, history, conversations, graph and tasks, with v1→v2 steps.
   - Seal the journal on run finish.
   - The single graph checkpointer.
2. **tinyflows**: flows, cron and adaptive. Drop its checkpointer copy for tinyagents-graph's.
3. **Modules**: tinymcp, tinychannels, tinyconnectors, tinywallet, tinybox, tinyjuice, tinyskills, tinymemes. Each one's grant becomes its schema.
4. **OpenHuman**
   - The `vendor/tinystoragedrivers` submodule and `[patch]`.
   - Compose the schemas.
   - Replace the host scope helpers.
   - Move host stores to v2.
   - Add the layout v2 move to `users/<id>/storage.db` and the migration CLI.
